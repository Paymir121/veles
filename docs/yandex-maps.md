# Подключение Яндекс.Карт

Карта в Велесе используется в двух местах:

- `/map` (`features/map/MapView.tsx`) — метки кладбищ, кластеризация, балун со списком
  похороненных;
- форма человека (`features/persons/PersonForm.tsx`, блок «Место захоронения») — карта для
  выбора точки мышью + **геокодирование** (`ymaps.geocode()`): клик по карте заполняет
  адрес/город, а введённый вручную адрес превращается в координаты при сохранении.

Технически это классический **JavaScript API v2.1** через обёртку
`@pbe/react-yandex-maps`; вся настройка изолирована в
`frontend/src/shared/maps/yandexMapsSetup.ts`.

## 1. Какой ключ нужен

Да, нужен именно **JavaScript API** — но с геокодером. В кабинете это продукт
**«JavaScript API и HTTP Геокодер»**: один ключ покрывает и отрисовку карты, и
`ymaps.geocode()`, который использует пикер места захоронения.

Бесплатные лимиты (с мая 2025 JS API и Геокодер тарифицируются раздельно, даже если ключ
общий):

| Что | Лимит бесплатного тарифа |
| --- | --- |
| JavaScript API (отрисовка карты) | 25 000 запросов в сутки |
| Геокодер (в т.ч. вызовы из JS API) | 1 000 запросов в сутки |

При исчерпании суточного лимита ключ блокируется до конца дня — для семейного дерева это
недостижимые цифры, но геокодер тратится на каждый клик по карте в форме.

Если в кабинете JS API и Геокодер предложены как два отдельных продукта с двумя разными
ключами — код сейчас умеет только один ключ (он же уходит в загрузчик JS API). В этом
случае нужно доработать `yandexMapsSetup.ts`, а не подставлять второй ключ куда попало.

## 2. Получить ключ

1. Войти в [Кабинет разработчика Яндекс.Карт](https://yandex.ru/maps-api/console) под своим
   Яндекс ID.
2. «Подключить API» → выбрать **JavaScript API и HTTP Геокодер** → «Продолжить».
3. Заполнить форму: ФИО, почта, телефон, краткое описание сервиса и ссылка на сайт,
   отметить соответствие условиям бесплатного использования и принять условия.
4. В разделе «Ключи API» скопировать значение ключа (UUID, 36 символов).
5. Там же, в настройках ключа, задать ограничение по домену(ам) — ключ всё равно попадает в
   публичный JS-бандл, домен — единственная реальная защита. Для локальной разработки нужен
   `localhost` (или оставить ключ без ограничений, пока проект не задеплоен).

Активация ключа может занять несколько минут — до этого карта отвечает ошибкой
авторизации.

## 3. Куда положить ключ

Переменная всегда одна и та же: `VITE_YANDEX_MAPS_API_KEY` (префикс `VITE_` обязателен,
иначе Vite не отдаёт переменную в браузерный код). Файл зависит от способа запуска:

| Запуск | Файл / место | Примечание |
| --- | --- | --- |
| Локально (`py main.py`, `npm run dev`) | `frontend/.env` | Vite читает `.env` **только из своего корня** (`frontend/`), корневой `.env` он не видит |
| docker-compose | корневой `.env` | Пробрасывается как build-arg в `frontend/Dockerfile` |
| Деплой через GitHub Actions | секрет `VITE_YANDEX_MAPS_API_KEY` в Environment `production` | См. `.github/workflows/deploy.yml` |

Шаблоны — `frontend/.env.example` и `.env.example`. Сами `.env` в `.gitignore`, ключ в
репозиторий не коммитим.

Vite подставляет `VITE_*` в бандл **на этапе сборки**, а не читает во время работы. Поэтому
после правки `.env` нужно перезапустить dev-сервер (`py main.py` заново), а для Docker —
пересобрать образ фронтенда (`docker compose build frontend`), недостаточно перезапустить
контейнер.

## 4. Проверка

1. `py main.py`, открыть http://localhost:5173/map — вместо сообщения «Не задан ключ
   Яндекс.Карт» должна отрисоваться карта России с метками кладбищ.
2. Открыть форму человека → «Место захоронения» → «Создать новое место» → кликнуть по
   карте: должны подставиться координаты и адрес/город. Это и есть проверка геокодера
   (карта может работать, а геокодер — нет, если продукт не подключён).
3. Консоль браузера не должна содержать сообщений вида `Invalid API key` /
   `apikey ... заблокирован`.

## 5. Если не работает

- **Карта серая или сообщение об ошибке авторизации** — ключ не активировался, домен не
  добавлен в ограничения, либо ключ из другого продукта (например, только Геокодер или
  MapKit для мобильных).
- **Карта есть, адрес по клику не подставляется** — не подключён Геокодер или исчерпан его
  суточный лимит (1 000).
- **Изменил `.env`, ничего не поменялось** — не перезапущен Vite / не пересобран Docker-образ
  (см. выше).
- **Сообщение «Не задан ключ Яндекс.Карт»** — переменная не дошла до фронта: проверить, что
  ключ лежит в `frontend/.env`, а не только в корневом `.env`, и что имя переменной точное.

## 6. Модули API загружаются по требованию

`@pbe/react-yandex-maps` подключает загрузчик с пустым `load=` и запрашивает у API только
те модули, которые нужны смонтированным компонентам. Следствие: всё, чего нет в этом
минимуме, нужно перечислять в пропе `modules` — иначе оно просто отсутствует, молча и без
ошибок в консоли.

Так был потерян балун на `/map`: у метки не существовало свойства `.balloon`, а свойства
`balloonContentHeader`/`balloonContentBody` игнорировались, поэтому выбор человека в поиске
центрировал карту, но ничего не открывал. Что используется сейчас (`features/map/MapView.tsx`):

| Компонент | `modules` | Зачем |
| --- | --- | --- |
| `Map` | `control.ZoomControl` | кнопки зума (по умолчанию карта без элементов управления) |
| `Clusterer` | `clusterer.addon.balloon` | балун кластера со списком мест |
| `Placemark` | `geoObject.addon.balloon`, `geoObject.addon.hint` | балун места и подсказка при наведении |

Пикер в форме человека получает геокодер через хук: `useYMaps(['geocode'])`.

Альтернатива — задать `query.load: 'package.full'` у провайдера и не думать о модулях, но
это тянет весь пакет API в браузер.

## 7. Юридический нюанс

Условия бесплатного тарифа формально требуют, чтобы сервис был общедоступен. У нас дерево,
карта и страница человека открыты без логина, а создание/редактирование — за логином; это
осознанный риск маленького некоммерческого проекта, а не гарантия соответствия оферте
(см. `AI_MEMORY.md`).
